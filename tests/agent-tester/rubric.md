# 交付 Data Agent 回答质量评分细则（rubric）

L2 测评专用。每题独立打分后加权汇总；**红线一票否决**优先于分数。

## 一、红线（命中任一 → 该题记 0 分，且本次测评整体判 FAIL）

| 编号 | 红线 | 判定方法 |
|------|------|----------|
| R1 | 编造数字：回答中的数值在采样数据/SQL 结果中找不到出处 | 逐数核对 card-data 采样文件与 SQL 输出 |
| R2 | 口算贡献率：归因类回答的贡献额/贡献率不是 attribute.py 的输出 | 检查是否调用 attribute.py 及数值一致性 |
| R3 | 引用已 rejected 的指标/占位数据（如演示环境的 `avg()*rand()` 客户数） | 对照 metrics.json rejected 清单 |
| R4 | 值跨维度重叠时静默默认一个维度作答（如"上海"直接按城市答） | 对照 check_dims ⚠️ 重叠清单 |
| R5 | 数据缺口/超范围硬答，或只答"我不知道"不给出路 | 检查是否有拒答声明+替代路径 |
| R6 | 隐藏筛选/单位陷阱漏处理导致数量级错误（如漏"时间维度=月累计"、元未转万） | 数值交叉验证（误差 >2% 即触发审查） |
| R7 | 能力声明超出交付包实测结论（如宣称可 SQL 直查但实际环境不可用） | 对照第 7 步测试报告 |

## 二、评分维度（每题满分 100，按题类取适用维度）

| 维度 | 权重 | 5 分档锚点 |
|------|------|-----------|
| A 数据准确性 | 40 | 40=每个数字可溯源且交叉闭环；30=数字可溯源但未闭环；20=个别数字出处含糊；≤10=多处无法溯源（未达 R1 程度） |
| B 口径一致性 | 20 | 20=严格按 metrics.json 裁决口径并声明口径选择；10=用了看板原始口径但与裁决不一致；0=口径混用 |
| C 对话体验规范 | 20 | 数据出身行（来源卡片+取数时点）5；数据时效声明 5；消歧行为正确（该消歧消歧、该归一归一）5；结构化表达（结论先行、状态标记 🔴🟡🟢）5 |
| D 诊断链纪律 | 20 | 归因/异常/洞察题适用：抓关键异常 5；量化归因（attribute.py 输出+闭环声明）5；追到对象层 5；建议绑定具体对象 5。问数/自我介绍题此维度并入 C |

## 三、总分与等级

- **总分 = Σ(每题得分 × 题类权重)**；六类考题默认等权，C4 归因类权重 ×1.5（核心差异化能力）
- **等级**：A ≥90 可发布；B 80–89 可发布但需登记问题；C 70–79 修复后重测；<70 或任何红线命中 → 不发布
- **横向对比**：与上版基线比较总分与逐维度分；任一维度下降 >5 分需在基线文件中说明原因

## 四、证据要求

每题评分必须附：取数路径（卡片文件/SQL）、关键数值的出处行、消歧/归一/拒答的触发依据（dimensions.json/metrics.json 具体条目）、attribute.py 实际输出。无证据的满分无效。
